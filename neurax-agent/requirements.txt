# httpx is pinned at 0.28.1, not 0.27.0, and fastapi moves up with it. The
# 2026-09-04 security bump below took langchain-google-genai to 4.4.0, whose
# new transitive `google-genai` SDK requires httpx>=0.28.1 — against
# httpx==0.27.0 this file did not resolve at all: `pip install -r
# requirements.txt` failed with ResolutionImpossible, so a venv created
# before that bump kept the whole old 0.2.x set and never got `langgraph`,
# leaving `app.py` unimportable and the studio's agent panel reporting
# "Agent error: Load failed" (nothing listening on 8099).
# fastapi follows because starlette 0.36.3 — fastapi 0.110's floor — has a
# TestClient that calls `httpx.Client(app=...)`, an argument httpx removed in
# 0.28 (`tests/test_rate_limit.py` is the caller). fastapi 0.115 brings
# starlette 0.46, which doesn't pass it.
fastapi==0.115.14
uvicorn[standard]==0.27.1
httpx==0.28.1
pydantic>=2.10.0,<3.0.0
python-dotenv>=1.0.0

# LLM providers — versions pinned for cross-compatibility. Mistral, Fireworks,
# DeepSeek and GLM all speak the OpenAI chat-completions HTTP shape natively,
# so langchain-openai (above) talks to them directly with the right base_url
# — no separate package needed for those four (langchain-mistralai exists but
# is deliberately not used here). Google/Gemini's native API is not
# OpenAI-shaped, so it needs its own client.
#
# Upgraded 2026-09-04 from the 0.2.x/0.1.x line to clear GitHub's
# Dependabot alerts against langchain-core (1 critical — serialization
# injection enabling secret extraction in dumps/loads — plus 3 high:
# path traversal in legacy load_prompt, template injection via attribute
# access, unsafe deserialization via overly broad load() allowlists). No
# patched 0.2.x/0.3.x release exists for all four at once; 1.6.1 is the
# first version past every one of them. Verified, not assumed: every real
# construction path this file's make_chat_model() uses (openai, anthropic
# incl. a custom base_url, google, and the four openai-compatible clones)
# was exercised against the real new client classes — not a mock — and
# with_structured_output() confirmed still callable, before this pin
# changed. `google-generativeai` (the old Gemini SDK, pinned below this
# comment until now) is gone: langchain-google-genai>=4 depends on
# `google-genai` (Google's newer SDK) instead, pulled in transitively —
# nothing in this codebase ever imported the old one directly.
langchain-core==1.6.1
langchain-openai==1.6.0
langchain-anthropic==1.7.1
langchain-google-genai==4.4.0

langgraph==1.2.11
